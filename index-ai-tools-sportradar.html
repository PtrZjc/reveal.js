Be aware of the context window!
128k tokens
platform.openai.com/tokenizer
Maximum single input to chat window:
  • ~120 kB
  • 30k-40k tokens
When providing a code, give instructions first
or divide a message into separate messages, writing at the end: WAIT THERE'S MORE
It reduces the risk of instructions being misinterpreted as part of the main content.
Use pseudo-language to give accurate instructions
Chat-GPT is very good in understanding any arbitrary notation system
Switch between the models when needed
The model can be changed after generating an unsatisfactory response
Consider data privacy
By default, input data is used to train OpenAI models. Disable model training in:
Settings -> Data Controls -> Improve the model for everyone
Also, the chat can be marked for automatic deletion after 30 days by enabling the "Temporary Chat" toggle.

Example prompt
Generate markdown table. I use "RXCX: content" notation to indicate a cell, where R is row, C is column and X is number.
Absent cells should be empty.
R1C3: Alice
R2C4: Bob
R5C1: fooBar

Format conversions

My Observations of GPT-4o
  • Shares the same context and limitations as GPT-4
  • Significantly faster
  • Often generates more content than requested, even when asked to limit output
  • Focuses less on details compared to GPT-4
  • Produces decent code quality, but sometimes makes stupid mistakes
  • Solid comparison benchmark
🔧   GPT-4
  • Reviews
  • Documentation
  • Whenever understanding whole context is needed
  • Complex refactoring
🔨   GPT-4o
  • Most of the coding tasks switching back to 🔧 when needed

Takeaways

🔍  Iterative process: from broad to detailed
💡  The fewer the details, the greater the variance
🔧  Customization reduces required details
📏  Keep the context size in mind
